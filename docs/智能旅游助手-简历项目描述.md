## 简历精简版

独立设计并持续迭代 AI 智能旅游助手，基于 `Vue 3 + TypeScript + FastAPI + OpenAI-compatible API + 高德地图能力` 输出结构化多日行程，并支持 Trip Workspace、固定预约、局部重规划、出发前预检、`.ics` 日历导出和地图可视化。  
设计多阶段 Agent 编排链路，串联 seed itinerary 生成、POI/酒店/天气/路线补全、结果归一化、预约约束注入与生成后覆盖审计；持续推动前后端热点模块拆分，将系统演进为可持续扩展的工程化产品底座。

## 简历详细版

### 项目名称

智能旅游助手 / Trip Planning Agent

### 技术栈

- 前端：Vue 3、TypeScript、Vite
- 后端：FastAPI、Pydantic v2、pytest
- 模型层：OpenAI-compatible API
- 地图层：高德地图 JS SDK、高德 MCP、Web Service fallback
- 存储层：Trip Workspace Store，支持 SQLite / JSON
- 工程化：Docker、GitHub Actions、前端构建校验、后端回归测试

### 项目定位

项目不是“让模型输出一段旅游文案”，而是面向真实出行场景输出可执行、可编辑、可重规划的结构化行程系统。  
用户不仅能生成结果，还能把结果保存成工作区，继续补充备注、录入固定预约、锁定部分日期、查看预约覆盖状态、刷新出发前预检，并导出到日历工具。

### 个人职责

- 负责前后端整体架构设计、主链路实现与持续重构
- 设计多阶段 Agent 编排链路，拆分 seed itinerary、事实数据补全、路线生成、后处理和诊断收口
- 设计并实现 Trip Workspace，支持请求快照、结果快照、版本演进、分享访问和持续编辑
- 设计并实现固定预约链路，覆盖预约录入、校验、请求注入、覆盖诊断和保底锚定
- 设计并实现工作区重规划，支持整日重生与 `fill_gaps` 缺口修复
- 设计并实现出发前预检刷新链路，支持天气、路线、营业时间、预约覆盖等检查项
- 推动前后端热点模块拆分，持续压缩超大文件和隐式耦合

### 关键成果

- 打通“生成 -> 补事实 -> 保存工作区 -> 继续编辑 -> 重规划 -> 预检 -> 导出”的完整链路
- 实现 Trip Workspace 持久化，支持草稿、结果快照、分享链接和锁定日期
- 实现固定预约能力，支持酒店、航班、火车、餐厅、门票等结构化预约录入
- 实现预约覆盖诊断 `reservation_coverage`，区分 `covered / unresolved / pending`
- 实现预约保底锚定，降低“真实预约未落到日程中”的风险
- 实现缺口驱动的单日补齐，已支持早餐、午餐、晚餐、加餐、活动、住宿、预约和整天日程
- 实现工作区最近一次重规划摘要 `last_replan_summary`
- 实现工作区出发前预检刷新与最近一次预检摘要 `last_precheck_summary`
- 实现预检多动作修复建议，例如“改室内活动”“调整出发时段”“压缩跨区往返”
- 实现 `.ics` 导出，支持将工作区中的预约、住宿和显式活动写入日历文件

## 面试口述版

我做的是一个面向真实出行场景的 AI 智能旅游助手。系统不是只生成一段攻略，而是输出结构化多日行程，并把结果保存成可持续编辑的 Trip Workspace。  
用户可以继续录入固定预约、锁定部分日期、按天补缺口、刷新出发前预检、查看最近一次重规划和预检摘要，最后还能导出 `.ics` 日历文件。  
我重点做了三类能力：一是多阶段 Agent 编排和事实数据补全，二是工作区和预约约束链路，三是前后端热点模块拆分和回归验证。

## 与普通 AI Demo 的差异

- 不是只生成文案，而是输出结构化 `TravelPlan`
- 不是一次生成结束，而是支持工作区持续编辑
- 不是把预约写在备注里，而是把预约作为正式约束参与生成和审计
- 不是只给“重试”按钮，而是支持缺口驱动的局部修复
- 不是只展示结果，而是支持出发前预检和导出
