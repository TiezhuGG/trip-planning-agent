# 智能旅游助手：竞品对比与功能路线图

## 版本说明

- 整理时间：2026-04-15
- 说明：以下判断基于 2026-04-15 可访问到的各产品官方公开页面与帮助文档整理，结论部分包含结合本项目当前代码现状做出的工程推断

## 1. 为什么现在要重新看竞品

这个项目已经不处在“能不能生成一份行程”的阶段，而是进入“能不能长期服务真实用户”的阶段。  
所以竞品对比的重点不再是 UI 风格，而是看四件事：

1. 用户已有资产能不能导入
2. 行程能不能持续协作和修改
3. 出发前和出发中还能不能继续提供价值
4. 结果能不能从“看一眼”变成“真能带走使用”

## 2. 竞品公开能力速览

### 2.1 Mindtrip

官方公开信息能看到的重点：

- AI 生成和编辑 itinerary
- 协作规划与分享
- 地图、收藏集、灵感发现
- Google Pins / 现有旅行资产导入
- receipt / confirmation 等旅行资料整理
- 移动端与在途使用

工程判断：

- Mindtrip 最强的不是单次生成，而是“已有资产导入 + 协作 + 行前到行中连续体验”
- 它对我们最大的启发不是聊天能力，而是资产沉淀和旅途中继续可用

### 2.2 Wonderplan

官方公开信息能看到的重点：

- 快速生成个性化 itinerary
- 预算、节奏、兴趣等基础偏好输入
- 页面内调整行程
- PDF 导出

工程判断：

- Wonderplan 更像轻量级 AI 行程生成器
- 强在低门槛、快出结果，弱在工作区演进、约束编辑和持续协作

### 2.3 GuideGeek

官方公开信息能看到的重点：

- 对话式旅行问答
- 通过 WhatsApp、Messenger 等入口触达
- 旅行建议、价格信息、本地推荐
- 更接近 concierge / assistant 体验

工程判断：

- GuideGeek 的优势是低门槛触达和“随问随答”
- 它对我们的启发是入口和在途使用场景，而不是结构化工作台本身

### 2.4 Google Maps

官方公开信息能看到的重点：

- 保存地点、清单、常用路线
- 分享列表和导航入口
- 出发 / 到达时间规划
- 地图级真实导航与 ETA

工程判断：

- Google Maps 的价值不在 itinerary，而在用户资产和高频入口
- 它是“导入能力”和“出发前/出发中服务能力”的最强参照物之一

## 3. 我们当前项目的位置

### 3.1 已经明显强于普通 AI itinerary Demo 的地方

- 结构化多日行程输出
- Trip Workspace 持续编辑
- 固定预约录入、校验和覆盖审计
- 锁定日期与局部重规划
- 地图、天气、路线的事实数据补全
- diagnostics、warnings、集成状态和 telemetry 收口

### 3.2 和成熟产品相比还缺的关键能力

- 导入用户已有收藏点和行前资产
- 导出到用户日历与外部工具
- 出发前二次校验
- 多方案比较和差异说明
- 收据 / 确认单导入
- 更细粒度的协作能力

## 5. 最值得补的功能，不是最多，而是最实用

### P0：优先级最高

#### 1. 预约硬约束排程

当前项目已经能把预约作为约束注入请求，并对结果做覆盖审计。  
下一步应把酒店入住、航班/火车、门票、餐厅时间窗显式压到 itinerary 槽位里，减少模型自由发挥空间。

价值：

- 直接提升结果可信度
- 降低“生成了但不能用”的概率

#### 2. 缺口驱动的一键补齐

当前前端已经能识别哪一天缺酒店、缺餐饮、预约覆盖不足。  
下一步应支持用户直接点击“补齐这一天的午餐”“补齐未覆盖预约”“补齐住宿缺口”，由后端做范围化重排。

价值：

- 把“发现问题”升级为“快速修复问题”
- 比整单重生更贴近真实操作路径

#### 3. 行程与预约 `.ics` 导出

把每日关键安排和预约导出到手机日历。

价值：

- 落地感极强
- 工程实现不算重，但用户感知价值很高

### P1：第二梯队

#### 4. Google Maps 收藏点 / 清单导入

允许用户把已有收藏点、列表或地址批量导入为候选 POI 或 must-visit 列表。

价值：

- 缩短用户从“已有资料”到“生成工作区”的路径
- 对标 Mindtrip 和 Google Maps 最现实的资产优势

#### 5. 出发前二次校验

在出发前刷新：

- 天气
- 营业状态
- 路线耗时
- 预约冲突

价值：

- 从“行前规划工具”往“出发前校验工具”迈一步
- 减少信息过期带来的失败体验

#### 6. 多方案对比与 diff

同一请求输出“省钱版 / 均衡版 / 深度版”三套方案，支持工作区级别 diff。

价值：

- 让 AI 生成更有“决策辅助”价值
- 更适合分享、比较和协作讨论

### P2：持续演进项

#### 7. 收据 / 确认单导入

允许用户上传邮件确认单、截图或票据文本，自动映射到预约草稿。

价值：

- 对标 Mindtrip 的 receipt 组织能力
- 和现有预约系统天然契合

#### 8. 更细的协作能力

在现有分享访问的基础上增加：

- 评论
- 变更记录
- 方案对比
- 分享页只读 / 可协作权限

价值：

- 让工作区从“可分享”进化成“可协作”

## 6. 推荐路线图

### 第一阶段

- 预约硬约束排程
- 缺口驱动的一键补齐
- `.ics` 导出

### 第二阶段

- Google Maps 收藏点导入
- 出发前二次校验
- 多方案对比与 diff

### 第三阶段

- 收据 / 确认单导入
- 分享协作增强
- 移动端 / 在途场景优化

## 9. 一句话结论

从竞品视角看，这个项目已经在“结构化结果、工作区、预约约束、局部重规划”上具备很强的工程基础；  
下一阶段最值得做的，不是重复做聊天入口，而是补“导入已有资产、把结果导出去、把预约变成硬约束、把缺口修复动作产品化”。
